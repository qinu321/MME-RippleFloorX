RippleFloorX ver 2.8
======================================================================

【它做什么】

  脚落地 → 在落点长出一圈涟漪，自己扩散约 5 秒后消失；
  连续走/跳 → 每个落点各一圈，叠成一串不同半径的环；
  站着不动（含播放动画时的 idle 摆动）→ 完全不出。

  不写死模型名：地板 .fx 声明离屏渲染目标，DefaultEffect 把 *.pmd/*.pmx
  都指向 RF_FootRipple.fxsub，换模型不用改文件。


【文件】

  RippleFloorX.x        地板配件（20×20 平面，y=0）
  RippleFloorX.fx       地板本体：读脚位、维护状态、画涟漪
  RF_FootRipple.fxsub   每个模型的「脚部报告器」（自动挂，Shift-JIS）
  RF_FootRing.fxsub     0.1 那版的脚环，留着当退路（见下）

  四个文件放同一个文件夹，载入 RippleFloorX.x 即可（MME 0.33+）。
  ★ .fx 与 .fxsub 必须同版，标记格式是两边共用的约定。


【使用】

  1. 载入 RippleFloorX.x，Y 设成地板高度 +0.1 左右。
  2. 拖模型进去：脚接触地面时出涟漪。
  3. 颜色/亮度：MMEffect → 效果参数里的 Ripple Color / Ripple Strength。
  4. 配件 Tr 仍然可以整体调透明度。
  5. 改了 .fx 之后必须重开 MMD 或重新载入配件（MME 不会热重编译）。


【怎么做的】

  子效果（每个模型）：脚接触地面时，往离屏缓冲底部写一个 4x4 像素小方块，
    颜色 = (地板局部 x, 地板局部 z, 0, 接触中=1)；不接触就把方块收缩成
    零点，什么都不写。

  地板：每帧读 16 个脚位，判断"这一帧有没有新的落地"，有就往队列头部插一条
    (x, z, 起始时间, 1+图案编号)，然后在地板平面上画队列里的环。

  状态纹理：1x32 的 RGBA32F（`RenderColorTarget`）：

    行   0-26（27 槽）涟漪队列
    行 27 / 28     每个模型对的上次出环时刻（对 0-3 / 对 4-7）——每模型独立节流
    行 29 / 30     每个模型对的上次落点（对 0-3 / 对 4-7）——用来判"滑步"
    行 31          脚部位掩码：第 f 位 = 槽位 f 上一帧是否踩在地上

  上一帧的状态用 `TEXTUREVALUE` 取（MME 在帧首把整张纹理塞进常量寄存器，
  32 个 texel 正好在限制内），所以没有双缓冲、也没有拷贝 pass。


【多模型 / 同一个模型载多份】

  16 个脚位 = 8 个「模型对」，每对 2 个槽（左/右）。模型对编号：

      cx = floor(センター.x / 32)    cz = floor(センター.z / 32)    ← 主判据
      rx = floor(全ての親.x / 8)     rz = floor(全ての親.z / 8)     ← 补判据
      pair = (VertexCount/8 + SubsetCount + cx + 3*cz + rx + 3*rz) % 8
      slot = pair * 2 + 左/右

  - 不同模型：VertexCount / SubsetCount 不同，自然分到不同的对。
  - **同一个 PMX 载多份**只能靠「摆位」分，主判据是 **センター**：多人舞蹈的
    摆位惯例就是给 センター 打偏移关键帧（所以摆位信息在那里）。
  - **「全ての親」只当补判据**：正经动作里它通常恒为 0，于是它贡献 0、完全不
    干扰主判据；只有两份模型的 センター 落进同一粗桶时，才靠根骨的细桶把它们
    分开。（早先两版先后拿根骨当主判据、拿 センター 单轴分桶，都是这个坑。）
  - 两个水平轴都参与（Z 权 3），横排一排、纵排一排都能分开。
  - 桶宽：センター 32 单位（粗一点，抗动作摆动）；全ての親 8 单位（细，它本来
    就不动）。
  - 最多 8 个模型，超过会循环复用槽位。
  - 同一动作载给多份时，动作对两根骨的位移对所有模型相同 ⇒ 相对分桶不变，
    所以动作本身不会造成撞槽。
  - 调试：DEBUG_HUD 改 1，A 带是 16 个小格（每 2 格一个模型），看哪几对在亮。
  - 撞槽了就调 fxsub 顶部的 CENTER_BUCKET（调小=更细），或把模型再拉开。


【!! 这台机器上的一个大坑（改这个效果前务必读）!!】

  这张 1x32 状态纹理的 **`.x` 通道读回恒为 0**，而 `.w` 正常。

  证据：同一行、同一个 pass、同一个值，写进 `.w` 能读到 1，写进 `.x`
  读回来就是 0。1.0~1.8 的十几轮"脚位状态读回 0 / 播放中静止一直冒"
  全部栽在这一点上，换 TEXTUREVALUE、换行号、换双缓冲、换静态坐标取样
  都一模一样地复发。

  所以：**任何标志位都不要放 `.x`**。现在的脚部掩码是四个通道都写、
  读的时候取 `.w`：

      return float4(mask, mask, mask, mask);   // 写
      float  prevMask = StateRow(MASK_ROW).w;  // 读

  队列行因为一直用的是 `.w`（有效位）/.z（时间）/.xy（位置），所以从来没
  出过问题——这也是为什么只有"脚位状态"坏了而涟漪一直是好的。


【调参】

  RippleFloorX.fx 顶部：
    RIP_MAX      5.0    涟漪寿命（秒）
    RIP_RADIUS   16.0   寿命结束时的半径（地板局部单位，地板是 ±10）
    RIP_BAND     0.04   三角/方/圆的线条粗细（半径的比例）
    RIP_LINE_W   0.15   线图案的线宽（局部单位）
    RIP_ROT      4.0    三角/方的旋转速度（弧度/秒）
    SLOT_COUNT   27     涟漪队列槽位（行 0-26）；容器放得下就尽量用满
    MASK_ROW     31     脚部掩码行
    FOOT_ROWS    8      脚位数量，要和 fxsub 的 FOOT_SLOTS 一致
    TRIG_GAP     0.40   每个模型自己两次出环的最小间隔（秒），Freq± 缩放它
    STEP_R       1.5    滑步判定：两脚中点比该模型上次出环时的中点移动超过这个量就算新一步
    DEBUG_HUD    0      改成 1 = 地板边画调试色带（见下）

  RF_FootRipple.fxsub 顶部：
    CONTACT_RATE 0.20   鞋底高度 / 小腿长 低于这个算踩住
                        （0.10 更灵敏、涟漪更多；0.25 更迟钝、更少）
    FOOT_THICK   0.22   踝骨到鞋底的高度（× 小腿长）
    FOOT_SLOTS   16     脚位槽数（要和 RippleFloorX.fx 的 SLOT_MAX 一致）
    CENTER_BUCKET 32.0  同一个模型载多份时，センター 的 XZ 粗桶（主判据）
    ROOT_BUCKET  8.0    全ての親 的 XZ 细桶（补判据，通常为 0）

  RIP_RADIUS = 16，地板是 ±10，所以图案会越过地板边缘再消失（约 3 秒到边）。
  地板放大（Si）时比例不变。


【四种图案】

  生成时决定并存进涟漪本身（状态行 .w = 1 + type）：
      type 0 放射线（短命，1.5 秒内淡出） / 1 旋转三角形 / 2 正方形 / 3 圆

  公式是 floor(开始时间) + 左右脚(0/1)，再对 4 取模 —— 左右脚固定错开一位，
  两只脚同时落地也一定是不同图案；每秒换一种。

  出生 0.15 秒内淡入，越往外越淡（1 / (1 + 半径×0.22)），
  最后 1.5 秒整体淡出，叠加上限 1.6。


【触发规则（2.0）】

  一只脚出涟漪，要同时成立：

    1. 这一帧踩住（鞋底高度 < CONTACT_RATE × 小腿长）；
    2. **满足下面任一条**：
       · 落地沿：上一帧它没踩住（正常的抬脚落下）；
       · 滑步：这个模型**两只脚落点的中点**，和它上次出环时记下的中点差超过
         STEP_R（1.5 局部单位）—— 专门救"脚贴着地滑、压根没抬起来"的动作，
         那种情况永远没有高度沿；
         ★ 必须用中点，不能拿单个脚去和"另一只脚的落点"比：左右脚相距 5-8 单位，
           那样比会让两只脚轮流"滑步"，站着不动也会一直出环（2.7 的 bug）。
    3. **这个模型自己**距上次出环超过 TRIG_GAP（0.40 秒）；控制器 Freq± 缩放它。

  第 3 条是**按模型**算的（2.4 起）：以前是全场景共用一个节流，5 个模型会互相
  抢，只有一个模型脚下出特效、还会在不同模型之间轮换。现在每个模型各算各的，
  互不干扰。

  **一帧最多可以入队 8 条**（每个模型对一条）：多人舞蹈里对齐帧数很容易、同帧
  落地几乎是必然，所以队列插入改成按"这一帧有几对触发了"整体前移，8 个模型
  同帧落地也全部保留（同一个模型两只脚同帧落地时只取先判定的那只）。


【多模型时的涟漪寿命（预算问题）】

  队列 27 槽、寿命 5 秒 ⇒ 全场可持续 **约 5.4 次/秒** 的出环量。

  - 1 个模型跳（约 2 次/秒）：富余，涟漪都能活满 5 秒。
  - 5 个模型同时跳（约 10 次/秒）：队列仍会饱和，最早的涟漪被挤掉，实际寿命约 2.7 秒
    —— 每个模型都有环，只是环短一些。
  - 想 5 个模型都活满 5 秒：把 TRIG_GAP 调大到 0.9~1.2（每个模型约 1 次/秒）。
  - 想更密：把 RIP_MAX 调小（调到 3 ⇒ 可持续约 9 次/秒）。
  - 状态纹理只有 32 行，再多槽位就没地方放「每模型节流」和「脚部掩码」了；
    真要更长的队列，得把这三样拆到第二张状态纹理里。


【控制器（可选，PMX 表情 / RippleFloorCtrl.pmx）】

  全部表情都是 0 = 不改变（不载入控制器、或载入了但表情为 0，效果与默认完全一样）。
  表情名必须完全一致（ASCII、区分大小写）。

    Hue+ / Hue-        色相顺时针 / 逆时针，1.0 = 转一整圈
    Bright+ / Bright-  亮度 ×3 / ÷3
    Freq+ / Freq-      每模型出环间隔（TRIG_GAP 0.40s）：÷3 更密 / ×3 更疏
    Life+ / Life-      涟漪寿命（RIP_MAX 5.0s）：×3 更长更大 / ÷3 更短更小
    Step+ / Step-      滑步阈值（STEP_R 1.5 局部单位）：×3 只认大步 / ÷3 轻微滑动也算

  Life± 的注意点：寿命变长会更快塞满队列（27 槽），所以 Life+ 拉满时最早的环
  会被提前挤掉；想看「又长又满」，得同时把 Freq- 往疏里调。
  Life± 只改寿命、不改最终半径（RIP_RADIUS 16），所以寿命变长时扩散会变慢、
  变短时扩散会变快。

  这几个参数在 RippleFloorX.fx 顶部的默认值：
      RIP_MAX   5.0 秒    涟漪寿命
      TRIG_GAP  0.40 秒   同一模型两次出环的最小间隔
      STEP_R    1.5 局部单位（地板是 ±10，所以 1.5 约等于地板宽度的 1/13）
      RIP_RADIUS 16.0     寿命结束时的半径


【排查】

  1. 完全没有：MME 版本；效果割当里 RippleFloorX 在不在、模型有没有挂
     RF_FootRipple；地板 Y 是否和模型站的平面一致。
  2. 打开调试色带：把 RippleFloorX.fx 顶部的 DEBUG_HUD 改成 1，重载地板。
     地板远边（-Z）会出现：
         A 带 16 个小格 —— 绿=这一帧在踩且上一帧也在踩；黄=刚落地（触发中）；
                          青=抬脚那一帧；黑=在空中
         B 带 27 个小格 —— 队列里各槽的年龄：白<1s / 黄<3s / 红<5s / 黑=空
         一条紫带 —— 这一版真的被编译进去了（看不到紫带 = MMD 还在用旧构建）
  3. 有环但位置偏：环心是踝骨在地板上的投影，脚背长的模型会偏一点。
  4. 环太大/太小/太快：RIP_SPEED / RIP_RADIUS / RIP_MAX。
